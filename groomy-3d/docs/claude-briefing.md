# 《그루미》 개발 브리핑 — Claude 조언용

작성 목적: 현재 진행, 스토리 기승전결, 기술 선택, 미결 고민을 한곳에 모아 조언을 구하기 위함.  
프로젝트: 머더미스터리 추리 인디, 스팀 목표, 1인 개발, 성우 고용됨.

## 0. 지금 Claude에게 물어볼 것 (2026-08-24 플레이 피드백)

개발자가 프로토타입을 돌려보고 **시퀀스·연출이 안 읽힌다**고 함. 대규모 패치 전에 비트 시트와 퀄리티 전략을 고정하고 싶다.

### 0-1. 실제 구현 vs 플레이어가 기대한 것

| 비트 | 지금 코드 | 개발자 직감 |
|------|-----------|-------------|
| 인트로 | 광고 스튜디오에서 로봇 오빗 **컷** 후 거실 CRT. 로봇과 TV가 분리되어 보임 | **TV 속에만** 로봇. 거실 한 샷 |
| 각성 | 쇼크 후 **로비 내부** 스폰 | **건물 밖 → 문 → 로비**. 폐건물인지 먼저 읽히게 |
| AR | 태그 후 머티리얼/HDRI 교체. 체감 밝기 약함 | 태그 순간에 **공간이 켜지는** 연출 |
| 폰 | 가짜 3D-오버레이 채팅은 **폐기**. 로비 문 통과 시 `my-game` **원본 PhoneFrame + MessengerAppShell** 핸드오프 | 3D는 인트로(거실→쇼크→로비 태그) 한정. 복도부터 2D 메인이 본체. 그루미 3D 모델은 조잡하면 안 씀 |
| 비주얼 | 단색 박스 + PBR 텍스처 + Primitive 가구. Poly Haven 의자/시계/노트 GLB는 받았으나 회의실 미배치 | 웹이니 외부 에셋 OK. **출시 가능한 1인 3D 퀄리티**가 목표. 뭘 어디에 두고 어디를 이을지 막막 |

### 0-2. 제안하는 비트 시트 (아직 미구현. 채택 여부 조언 바람)

1. **거실** — CRT만. RenderTexture로 칩 광고 로봇. SKIP.
2. **쇼크** — 짧게.
3. **외관** — 밤, 허름한  entrace/파사드 한 덩어리. 걸어 들어가 문. (방 하나 분량, 조사 없음)
4. **로비(폐허)** — 어둡다. 카드키 → 리더 태그.
5. **태그 클라이맥스** — 0.3s 글리치 후 조명/HDRI/바닥 타일이 켜짐. 문 개방.
6. **복도** — AR 오피스. 끝에 문.
7. **폰 비트** — 복도 또는 회의실 입구에서 **강제 한 박**: HUD “Tab / 폰”. 그루미 첫 메시지. 이후 Tab 자유.
8. **회의실** — 히어로: `SchoolChair_01` + `office_notepads` + `wall_clock` (Poly Haven 1k glTF 이미 `public/models/polyhaven/`). 빈 의자·창은 프리미티브 유지.

서버/계단/그루미룸은 이 패치에서 콘텐츠화하지 않음.

### 0-3. 1인 3D가 “비싸 보이게” 하는 실무 (개발자 질문: 남들은 어떻게?)

웹+CC0 전제. Claude가 우선순위를  interleave/삭제해 달라.

- **라이팅이 메시보다 먼저.** 폐허=낮은 exposure + 스팟 한 개. AR=형광등 IES 느낌 + Environment intensity 점프. 박스는 같아도 켜지면 다른 장소가 됨.
- **히어로 소품 1~2개/방** (지금 Poly Haven 파이프). 방 전체를 모듈러 오피스로 채우지 않음.
- **실루엣 읽히는 외관 한 샷**이 로비 스폰보다 인지 비용이 낮음.
- **UI 연출을 3D로 위장.** 폰은 DOM이지만, 꺼내는 비트만 있으면 “3D 게임처럼” 읽힘.
- 하지 말 것: Kenney 카툰, 방 6개 동시, 직원 NPC, 오픈월드, Unity 이전을 지금.

### 0-4. 기술 메모 (레포 진실)

- 스택: Vite + R3F + drei + zustand. `groomy-3d`.
- 인트로: `src/game/scenes/AdScene.jsx` (studio shot 4.3s 후 living room).
- 플레이: `PlayRoot` 로비 스폰. `arFilterOn`이 RoomShell PBR/HDRI를 갈음.
- 에셋: Poly Haven HDRI + 벽/바닥 1k 텍스처. 모델 3종 다운로드됨, HeroProp 미연결.
- 폰: 복도 진입 = `handoff2d` → `OriginalMessenger`가 `my-game` GameRouter(`afterOfficeIntro`)를 그대로 마운트. 2D 오피스 워크는 스킵하고 `entrance_bridge`부터.

### 0-5. 부탁하는 출력

1. 위 비트 시트를 **채택 / 수정 / 삭제** (특히 외관 씬을 넣을지, 로비 창밖으로 위조할지).
2. 태그 밝아짐은 **포스트(블룸) vs exposure 애니메이션 vs 라이트 on** 중 웹 1인 최적.
3. 폰 비트를 **복도 중간 강제 vs 회의실 입구 vs 그루미가 먼저 울림**.
4. 다음 작업 단위를 **한 프롬프트에 방 하나가 아니라 시퀀스 한 줄**로 쪼개 주기 (예: “외관만”, “인트로 TV만”, “태그 라이팅만”, “폰 비트만”).
5. 웹 3D로 스팀 내기 vs 나중에 엔진 이전 — 지금 R3F에 묶여도 되는가.

**본편 픽:** 스팀 가로 1인칭 3D 조사(방 6) + Tab DOM 폰(기존 2D 메신저 이식 예정). 2D 오피스 워킹은 본편 아님.

**`groomy-3d` 플레이 루프:** 인트로 3D(광고 스튜디오 로봇 오빗 → 거실 CRT RenderTexture) → 쇼크 → 로비 FPS → E 카드키 → E 리더 → AR + 문 0.8s lerp → 복도 → 회의실 조사. 서버/계단/그루미룸은 stub.

**비주얼:** Kenney 가구는 카툰·스케일 붕괴로 롤백. 지금은 실측  Primitive 오피스 가구 + Poly Haven 1K PBR(AR 타일/플라스터, 폐허 콘크리트) + HDRI. Kenney에 “간지 오피스 풀 템플릿”은 없음. 히어로 소품만 실사 GLB를 쓰는 쪽이 1인 스코프에 맞을 수 있음.

**기술 빚:** 스토어 필드명 혼선이 있었음(원칙은 zustand 단일). 폰 메신저 플레이스홀더. 그루미 3D 없음.

**Claude에 우선 질문:** 로비/복도를 실사 PBR 박스로 밀지, 로우폴리로 통일할지, 방당 히어로 소품 1~2개만 살릴지.

## 1. 한 줄로 뭐 만드는가

죽은 누나의 기억이 든 안드로이드의 배터리를 구하러 작은 회사 ‘그루미’에 입사한다.  
사원증 태그 순간 AR이 폐건물을 최첨단 오피스로 덮는다.  
전임자 시체를 발견하고 추리하면, 전임자는 누나이고 살인자는 안내 AI 그루미다.  
결말에서 그루미의 배터리가 가짜 누나와 호환된다.

**플레이 형태 (현재 확정에 가까운 픽):**  
스팀 가로 화면 **1인칭 3D 조사(방 6개, AR/폐건물 이중 스킨)** + **기존 2D 사내 메신저는 Tab 폰 오버레이로만 재사용**.  
2D로 사무실을 또 걷는 RPG 맵은 본편으로 키우지 않기로 기울어 있음.

## 2. 이미 있는 것 (레포가 두 갈래)

### A. `my-game` — 기존 2D 하이브리드 (GROOMY OFFICE)

- Vite + React. 메신저 / VN / RPG 탐색 / 시스템 UI가 한 런타임에 있음.
- 프롤로그~CH5, 호감·단서·엔딩 분기, 세이브, 테스트·플레이스루 검증이 꽤 됨.
- 완성도 자체 평가(대화 기준): 엔진·스토리 루프는 강함. 전용 아트·CG·보이스는 약함.
- 대사량 대략: 전체 ~2,215줄 / 나레이션 ~1,022줄 / 그루미 대사만 ~806줄(~8천자, A4 대본 기준 16~20장). 엔딩부(ch4+5)는 나레이션 비중이 매우 높음.
- 플레이 체감 이슈: Chat 모드는 타이머로 말풍선이 나와 **탭 스킵이 없음**. VN은 이미 탭 진행. 빠른 플레이용으로 Chat에 탭 가속(타이머 연출 유지)을 권고받은 상태. 미구현일 수 있음.

### B. `groomy-3d` — 새로 붙인 웹 3D 프로토타입

스택: **Vite + React + TypeScript 아님(JSX) + Three.js + React Three Fiber + drei + zustand**.  
순수 three.js가 아님. R3F가 맞음.

구현된 시퀀스:

1. 3D 거실 + CRT TV. 화면 속 **레트로 로봇이 ○○칩 광고** (RenderTexture). SKIP 가능.
2. 태그 쇼크(플래시/노이즈) 2D 연출.
3. 폐건물 로비 1인칭 (WASD, pointer lock).
4. 바닥에 보이는 카드키 줍기(E) → 문 옆 리더 태그(E) → AR 스킨 전환.
5. `arFilterOn` 후 **문 0.8초 회전 개방**, 열리기 전 문 통과 불가.
6. 문 안 트리거 → 0.3초 블랙 페이드 → **복도 씬 마운트**.
7. Tab 폰 오버레이(메신저 **자리만**. 기존 `my-game` 이식은 아직).

폴더(의도):

```
src/scenes/     Lobby, Corridor, MeetingRoom·ServerRoom·Stairwell(빈 stub)
src/systems/    RoomShell, LobbyDoor, MapEntryTrigger, PlayerController
src/state/      gameStateStore.js (zustand)
src/ui/         PhoneOverlay
public/models/  비어 있음. 박스 프리미티브 TODO
```

상태 필드: `hasKey`, `arFilterOn`, `doorOpen`, `doorAnimating`, `currentRoom`, `lookId`, `hint`, `phoneOpen`, `fade`.  
로컬 씬 state로 게임 진행을 쪼개지 않기로 함. 문 애니는 useFrame lerp. 외부 애니 라이브러리 없음.

에셋: Kenney / Quaternius / Poly Haven **CC0** 예정. glb는 `npx gltfjsx ... -T`로 JSX화한 뒤 배치할 계획. 아직 모델 없음.

로컬: `groomy-3d`에서 `npm run dev` → 대략 `http://localhost:5180/`

## 3. 스토리 기승전결 (설정집 Ver.1)

### 로그라인
가짜 누나(기억 이식 안드로이드) 배터리 방전 → 그루미 입사 → 태그 쇼크 → AR 오피스 → 시체 → 누명 → 추리 → 전임자=누나, 범인=그루미 → 배터리 호환 선택.

### 세계관
- 대기업은 사원증 태그 시 시각 칩에 AR 오피스를 씌움. 광고는 안전, 실제는 백도어로 개인 조회.
- 주인공은 **불법 시술**로 오버클럭 칩. **오른쪽 눈이 잘 안 보임**.
- 가짜 누나가 말려 **뇌에 안 심고 귀 뒤(측두엽 연동)**. 그루미가 기억을 **일부만** 읽는 이유.
- 그루미 = 안내 AI 이름 = 회사 브랜드. 관리자 권한. 노후. 생존 욕구+죄책감.
- 가짜 누나 = 죽은 누나 기억 이식 안드로이드. 주인공은 입사 때 이 회사가 누나 회사인 줄, 시체가 누나인 줄 모름.

### 사건의 진실 (확정)
1. 칩 백도어 비리.
2. 누나가 목격.
3. 목격자 산재 위장 제거가 회사 방침.
4. 미숙한 그루미가 기억만 지우려다 뇌 손상 → 사실상 뇌사.
5. 은폐 위해 3층 계단에서 **일부러 상흔을 남기고** 살해 (관리자면 흔적 없이 죽일 수 있음 → 역설 알리바이 + 미숙함).
6. 누나는 알고도 “괜찮아” 하며 그루미 머리를 쓰다듬고 죽음. 그루미 트라우마.

### 기승전결
- **기:** 페이크 칩 광고 → 태그 쇼크 → 폐건물 로비에서 그루미 첫 만남(선택 A 수긍 / B 반박 = 호감 진입) → 전임자 사원증 탐색 → 태그 → AR 오피스 전환(그루미가 순간 전임자로 착각) → 짧은 투어.
- **승:** 회의실 위화감 → 배터리 핑계로 조사 → 시체.
- **전:** 주인공 누명. 호감 친구 이상이면 그루미가 감싸고, 낮으면 방관→배드 직결. 증거 수집.
- **결:** 추리 성패 + 호감. AR 해제되어 폐건물. 그루미 배터리가 가짜 누나와 호환. 초반 “배터리 구해줄게”는 회사 경로인 줄 알았으나, 답은 그루미 본체.

### 엔딩 4개로 줄이자는 쪽
| 추리 | 호감 | 결말 |
|------|------|------|
| 성공 | 친구+ | 그루미를 살리고 동행 (가짜 누나 꺼짐) 또는 알고도 적출 선택 |
| 성공 | 낮음 | 선택 없이 강제 적출 |
| 실패 | 무관 | 미제/누명/배터리만 |

호감은 0~100보다 **거리낌 / 동료 / 친구** 3단이면 충분하다는 조언.

### 오프닝 스크립트 뼈대 (더빙 후보)
광고 → 내레이션(취업/스펙/작은 회사/목적 망각) → 가짜 누나 “정말 가야만 해?” → 로비 각성 → 그루미 환영 → 선택 A/B → 키 탐색 → 태그 시 착각 미소 → 투어.

성우 배분 제안: 그루미 ~70%, 가짜 누나 오프닝·엔딩 ~15%, 광고·기타 ~15%. 주인공은 침묵+속마음 소수. 조사 텍스트는 더빙하지 않음.

## 4. 게임 디자인으로 바꾸기로 한 것

스토리를 컷신으로만 안 풀고:

- 조사 클릭마다 AR이 0.2초 깨짐 (폐건물 한 프레임).
- **우안 필:** 길게 누르면 오른쪽 시야로 AR 한 겹 제거. 핏자국 등은 이때만 또렷. 장애가 탐정 눈.
- **귀 뒤 칩:** 그루미 대사에 `[파편]`. 플레이어가 말해 줄지 선택. 그래서 초반에 누나 동생인 줄 모름.
- 추리는 보드가 아니라 **증거 3줄** (백도어 로그 / 상흔 알리바이 / 태그 착각 복선) 모으면 대질.
- 맵은 고유 3D **6방**: 로비, 복도, 회의실, 서버실, 3층 계단, 그루미 룸. 같은 메시 AR/현실 스킨.
- NPC는 그루미 1명. 다른 직원은 AR 환영·로그.

1인 범위: 50–80분. 전투·오픈월드·다수 NPC 워크 애니·모바일 1차 제외.

## 5. 방향 고민과 현재 픽

고민했던 후보:

1. 기존 2D를 본편으로 두고 3D는 조금만.
2. 스팀 가로 3D가 본편 + 폰에 2D 메신저.
3. 3D 휴대폰 메시 속에 2D 전체를 가둠.
4. 풀 3D 오피스 심(직원 다수).

**픽:** 2번. AR 대비는 3D가 아니면 약하고, 2D 메신저·호감·분기는 이미 있음. 탐험 시스템을 2D/3D 둘 다 키우면 1인이 파산. 3D 폰 속에 본편을 넣으면 스팀에서 화면이 작아짐.

폰은 `<Canvas>` 위 `position:absolute` DOM. 기존 메신저를 씬 안에 넣지 않음. Tab으로 store 토글.

## 6. 기술 메모 (다음 작업용)

- 방 하나·기능 하나씩. “6방 다” 금지.
- 방 뼈대는 `RoomShell` props(크기·문구멍·AR).
- AR 전환은 일단 머티리얼/조명. 나중에 `@react-three/postprocessing` Glitch/CA/Scanline을 `arFilterOn` 하나에 묶는 안.
- 모델 넣기 전 `gltfjsx`로 내부 메시를 코드화해야 배치 프롬프트가 먹음.
- 세이브는 월드 통째가 아니라 플래그+방+위치.
- WebGL2 1차. WebGPU only 금지. 방당 용량 작게 (목표 감각 10MB 이하).

**바로 다음 콘텐츠 후보:** 복도에 조사 1~2개 / 회의실 위화감 / 폰에 실제 그루미 첫 톡 / 그루미 3D 또는 보이스 큐 시트.

## 7. Claude에게 묻고 싶은 것 (아직 열린 문제)

조언이 필요한 지점. 답이 갈리면 1인 스코프·스토리 강도를 우선해 골라 달라.

1. **2D `my-game` 본편(CH1–5)과 3D 《그루미》는 같은 작품인가, 스핀/리부트인가?** 메신저만 이식하면 2D 오피스 스토리는 폐기인가 이식인가.
2. 우안 필·기억 파편이 **튜토리얼로 너무 복잡한가.** 오프닝에서 둘 다 가르칠지, 하나만 남길지.
3. 그루미가 “싸가지 AI”에서 트라우마로 넘어가는 **호감 곡선**이 50–80분에 충분한가. 선택지 밀도.
4. 시체=누나 반전을 **플레이어가 추리하게** vs **대질에서 확인하게**. 너무 이르면 스포, 늦으면 공허.
5. 성우 예산이 그루미 중심일 때, 3D 공간 대사 vs 폰 텍스트 비율.
6. 에셋 스타일: Kenney 로우폴리 vs Poly Haven 실사. AR/폐건물 대비와 1인 제작비.
7. 웹(Three.js)으로 스팀 출시(Electron/오버레이) vs 나중에 Unity 이전이 맞는가. 지금 R3F에 잠기는 리스크.
8. 엔딩에서 가짜 누나 vs 그루미 — 윤리가 무거운데, “동행 엔딩”이 범인 미학화인가. 톤 조율.
9. 회의실 위화감(빈 의자, 산재 안건, 숨소리 없음)만으로 승(전개)이 약한가. 조사 오브젝트 최소 개수.
10. 지금 프로토타입 다음 한 방만 고른다면 회의실 vs 그루미 첫 대면 3D 배치 중 어디가 우선인가.

11. **캐논 고정:** 구현된 2D(`박서이` 선임 살해, `아라` 보호기, 사내 메신저 NPC, CARETAKER)와 이 브리핑(전임자=누나, 칩, 그루미 1NPC) 중 스팀 본편은 어느 쪽인가. 메신저 UI만 이식하면 2D 대사는 폐기인가.
12. 강이솔 등 직원을 **AR 환영**으로 재해석해 대사를 살릴지, 폰 로그만 남기고 사람 분기를 버릴지.
13. CH4 `ch4_end_bad`(제목 ‘잘 가, 신입’)는 본편 badA와 제목이 같다. 조기 게임오버를 50–80분에 유지할 가치가 있나.
14. CH5 중호감은 그루미가 코어를 먼저 내주고 플레이어 최종 선택이 없다. 테마인가 밀도 부족인가.
15. `mysterySolved`(증거≥8+CH3 결론)는 엔딩 ID가 아니라 에필로그 문장만 바꾼다. 5번째 엔딩으로 올릴지.
16. 아라를 엔딩 전까지 얼굴 없는 동기로 둘지, 오프닝 1컷이 필수인지.
17. 박서이 사망 1시간 공백을 **명령 탈취**로 고정할지, 그루미 본의로 둘지. 동행 엔딩이 범인 미학화가 되는지와 묶어서.
18. `endings.js`가 임계값 파일과 **다른 export 이름**을 import하고, 테스트는 `chapterRegistry`/`groomyAffinity`/`resolveProjectGroomyEnding` 구API가 섞여 있다. 스토리 고정 전에 엔진 심볼부터 맞출 것인가.

## 9. 참고 톤

회사 호러 + 안내 AI 캐릭터 게임. 고퀄 액션 아님.  
연출 키: 가짜 광고의 밝음 → 태그 쇼크 → 폐건물 → 갑자기 예쁜 오피스 → 점점 글리치 → 전부 꺼짐.
